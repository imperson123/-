# 基准测试与 Baseline 设计（LUT-SA / 鸿蒙玲珑核）

> 目的：把"我们的模型/算法/工程好在哪"变成**可复现、可对标、口径干净**的比较。
> 本文给出：① 已测数据 ② 推荐的 Baseline 矩阵 ③ 受控变量与口径 ④ 缺口与补齐成本 ⑤ 叙事结构。

## 二、推荐的 Baseline 矩阵（5 组对照，各自只证明一件事）

> 原则：**一次只动一个变量**；每组对照必须回答一个句子级结论；所有组都用同一套口径与工具。

### A. 同设备（HarmonyOS）——证明"计算路径/系统设计好"

**A1. 同权重 × 同设备 × 不同计算路径（核心对照）**
- 受测：T-MAC LUT 内核（本 App）
- 基线（两种，分别标注）：
  - (i) **同权重**：llama.cpp 自带 BitNet/三值内核跑同一份 BitNet-3B 三值权重 → 纯"计算路径"对比（最公平）
  - (ii) **同源不同精度**：同一源模型的 Q4_0 量化（~4.5 bit）→ 作为"更高精度参照"，须明确标注精度差异
- 工具：`llama-cli` / `llama-bench`（aarch64-ohos / x86_64-ohos 交叉编译，同一 OHOS SDK）
- 口径：decode 阶段 tok/s、TTFT、峰值内存；固定线程数、提示词、生成长度
- 结论句：*"同一权重、同一设备，LUT 查表路径比'反量化+浮点乘加'路径快 N 倍"*
- 状态：**缺**（需编译非 T-MAC 的 llama-cli 并推入设备，约 1–2 h）

**A2. 同实现 × 同设备 × 记忆策略开关（消融）**
- 受测：链式 KV 开启；基线：链式 KV 关闭（等效"每轮全量 prefill"）
- 现有等效基线：首轮数据（复用 0）+ 追加式提问（复用 6/13）
- 建议补：代码加"禁用记忆链"调试开关，可一键出 A/B（成本低，30 min + 重验）
- 结论句：*"重复/追加式问答的首字延迟从 ~240 ms 压到 sub-ms 级，且随复用比例单调下降"*

**A3. 同应用 × 同设备 × 调度策略开关（已具备）**
- 受测：L2 调度开；基线：关（对照实验已完成：释放 1.30 GB vs 0）
- 结论句：*"后台停留 70 s，调度开释放 1.30 GB、关则 0——同机同模型，唯一变量是调度"*

### B. 跨平台横向——证明"结论不是单机偶然"

**B1. 同模型同内核 × 多设备**：M2-Ultra / Raspberry Pi 5 / AGX Orin / 鸿蒙真机 / 鸿蒙模拟器
- 结论句：*"优势在算力越受限的设备上越明显（Pi5 单核 5.9×），且可移植到鸿蒙"*
- 状态：**已具备**（初赛表 + 本次鸿蒙数据）

### C. 模型维度纵向——证明"端侧适配好"

**C1. 同源模型 × 不同精度**（fp16 / Q4_0 / 2.44 bit）：体积、峰值内存、tok/s 三角
- 结论句：*"2.44 bit 把模型压到 0.99 GB（fp16 的 1/6.6），并以 Q4_0 的实现路径为速度对照"*
- 注意：**不同精度质量不同**，文中必须并列声明，不做"同质量"暗示

### D. 工程维度——证明"交付与工具链好"

**D1. 构建配置对照**：ASan 注入 vs 纯净（2.4×）
**D2. 内核级基准**：m128-k3200 · 200 次 · 7.8 µs/次（消掉端到端噪声）
**D3. 交付闸门**：安装 / 启动 / 渲染 + 离线验签（官方通知第 2 条的自证）
- 结论句：*"性能结论可在纯净构建下一键复现；交付包三闸门自测通过"*

## 三、口径与受控变量（写报告必须固定）

1. **受控**：同一设备、同一模型文件、同一线程数（4）、同一提示词与生成长度（32/256 token）、同一构建配置（纯净、无 ASan）、设备空载且温度稳定
2. **重复**：每组 ≥3 次取中位数，标注最大偏差
3. **口径**：
   - 吞吐 = decode 阶段 tok/s（`llama_perf` 的 eval time），不含加载
   - TTFT = 请求起点（含前缀处理）→ 首 token
   - 内存 = 引擎 `VmHWM` + `hidumper --mem` 交叉验证
   - 提示词长度与生成长度必须随每个数字一起给出（本次已发现：同一手机 256 token 生成比 32 token 低 ~13%，属正常 KV 增长）
4. **禁止**：跨设备直接比 tok/s 而不标设备（M2-Ultra 4 线程 54 tok/s 与手机 20 tok/s 不能并列暗示同一水平）
5. **稳定性**（实测记录）：真机重复同配置偏差 <1%（17.55 / 17.66 tok/s）；**模拟器受宿主机负载影响大**
   （同配置 10.21–25.01 tok/s），涉及模拟器的对比须标注区间，跨平台结论以真机为准
6. **提示词/生成长度必须随数字给出**：同一手机 256 token 生成比 32 token 低约 13%（KV 随长度增长，属正常）

## 五、叙事结构（把好说清楚，不吹）

1. **主叙事（算法好）**：同权重、同设备、跨实现 → LUT 路径快 2.5–5.9×（来源：A1 + B1）
2. **副叙事 1（系统设计好）**：同权重、同路径、跨轮记忆复用 → 重复提问 TTFT 240 ms → sub-ms（来源：A2）
3. **副叙事 2（系统友好）**：同应用、跨调度策略 → 后台释放 1.30 GB（来源：A3）
4. **副叙事 3（端侧适配）**：同源模型、跨精度 → 0.99 GB ≈ fp16 的 1/6.6（来源：C1，声明质量差异）
5. **工程与交付**：纯净构建 2.4× / 内核 7.8 µs / 三闸门 + 验签（来源：D1–D3）
6. **诚实边界（主动写）**：未在鸿蒙跑 7B；功耗未采集；应用内不支持标准量化格式（Q4_0 基线走 CLI）；复用会改变采样轨迹（多次生成输出不逐字一致，属采样随机性）
