# 待验证事项

1. **模型导入覆盖**：`Index.ets` 在完成复制和大小检查前以 `TRUNC` 打开固定的 `model.gguf`；若复制失败或空间不足，原文件可能已经被覆盖。错误分支中“已保留原模型未变”的提示与代码不符。应改为临时文件、完整校验后原子替换，并在设备上验证异常与恢复路径。
2. **沙箱权限**：`napi_init.cpp` 的 `PrepareSandbox` 与加载路径为 `hdc file send` 开发捷径将目录设为 `0777`、模型文件设为 `0666`。这会放宽本地文件权限，且不是文件选择器导入所必需。应区分开发构建与发布构建，再在真机上验证更严格的权限。
3. **模型格式**：随包的对比记录显示标准 Q4_0 GGUF 在当前 T-MAC 构建中触发原生崩溃。加载前应增加明确的格式检查和错误提示；本次未改变加载路径。
4. **验证范围**：本次迁移未完整编译、运行 HAP、加载模型或断网复测。SystemAbility 组件是实验性代码；零售版设备的权限边界见 `ohos/SA-BOUNDARY-EVIDENCE.md`，不能把原型描述为已安装的系统服务。
